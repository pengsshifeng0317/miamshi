## Java：`==` 和 `equals` / `hashCode`

- **错在哪**：2026-08-31 天融信一面答成"equals 比较**哈希值**"，把 equals 和 hashCode 混为一谈。
- **正确答法**：
  - `==`：比较**引用地址**（基本类型比较值）。
  - `equals`：Object 默认实现就是 `==` 比地址；String / Integer 等**重写后比较内容**（不是哈希）。
  - 约定：**重写 equals 必须重写 hashCode**——相等对象哈希必须相等，否则 HashMap / HashSet 会错。
- **关联逐字稿**：面试题目/八股基础/Java集合与并发.md（待生成）

## Java：HashMap 初始容量与扩容

- **错在哪**：2026-08-31 天融信一面把默认初始容量答成 **8**。
- **正确答法**：默认**初始容量 16**、**负载因子 0.75**，扩容阈值 = 16×0.75 = **12**，超过即扩容为 **2 倍**；JDK8 起链表长度 ≥8 且桶 ≥64 时转红黑树。

## Java：线程池参数（IO 密集型）

- **错在哪**：2026-08-31 天融信一面现场编"核心=CPU 数、最大=2 倍 CPU"，IO 密集这个配置偏保守，且没落到项目真实参数。
- **正确答法**：
  - 7 个参数：核心线程数、最大线程数、空闲存活时间、时间单位、工作队列、线程工厂、拒绝策略。
  - IO 密集合理线程数 ≈ `N×(1 + 等待时间/计算时间)`，通常取 2N 或 2N+1，不是"N 核心 / 2N 最大"这种保守配置。

## 缓存：穿透 / 击穿 / 雪崩的解法归属记串

- **错在哪**：2026-09-03 小熊博望一面把「过期时间加随机漂移打散」这个**雪崩**的解法安到**击穿**头上；击穿漏了互斥锁 / 逻辑过期；雪崩整段解法没给。定义会、解法乱 = 没背熟。
- **正确答法**：先分清本质——穿透=数据本身不存在（缓存和库都没有）；击穿=单个热点 key 过期瞬间超高并发；雪崩=大批 key 同时失效或 Redis 整体不可用。
  - **穿透**：缓存空值（带短 TTL）+ 布隆过滤器前置 + 入口校验。
  - **击穿**：互斥锁（只放一个请求重建缓存，其余等待/返旧值）；逻辑过期（物理永不过期，异步重建读旧值）；热点永不过期。
  - **雪崩**：过期时间加**随机值打散**；多级缓存（本地+Redis）；熔断/限流/降级；Redis 高可用 + 持久化。
- **关联逐字稿**：面试题目/八股基础/数据库与Redis.md（待生成）

## MQ：消息丢失 / 重复（自己项目就有 RocketMQ 却卡壳）

- **错在哪**：2026-09-03 小熊博望一面 Q5，只说了「抖动没到 broker 做重试」就卡壳，主动喊停重来且没接上。自己项目就用了 RocketMQ，这题本不该卡。
- **正确答法**：先说「我们项目就用 RocketMQ，按三段讲」给骨架。
  - **丢失三环节**：生产端用**事务消息**（本地事务+回查）保证「本地操作+发消息」原子；Broker 靠主从/持久化；消费端**处理成功再提交 offset**，别 auto-ack。
  - **重复**：消费端幂等——框架层 `@IdempotentConsume`（Redis SET NX + CONSUMING→CONSUMED 状态机）+ 状态机 guard 兜底；实际去重靠 MessageWrapper.uuid 作 MQ keys + 事务回查。
  - ⚠️ 诚实边界：幂等组件目前未真正打在监听器上，简历/面试别说「所有消费者都走幂等注解」。

  - 文档过期→回答带引用 + EvidenceGate 质量闸门 + 记忆「冲突以本轮为准」兜新旧。

## 线上排障题：跳过「先止血」、把 TTL 往事当第一步

- **错在哪**：2026-09-03 小熊博望一面 Q15（首字 4s→12-13s、检索效率 90→80%，30 分钟排查）：面试官明确要「先止血→定位根因→看哪些监控/日志/资源」，你却把「traceId 线程私有→用 TTL 解决」的往事当第一步（跑题），没答止血。
- **正确答法**：四步骨架——① **先止血**（~5 分钟）：判断最近发布→回滚；模型通道慢→降级/切备用/调低全局限流 max-concurrent；必要时扩容。② **定位**：挑一条慢请求沿 trace 逐段量耗时（意图打分→问题重写→检索 RRF+Rerank→记忆 load→LLM 首 token），分级看资源/队列(信号量 10 是否打满)/模型通道。③ **抓线索**：检索效率 90→80 正对应评测目标 Doc Hit@5 ≥90% 掉线 → 查最近检索层变更（换 embedding/动阈值 0.35/0.4/0.6/改意图树）+ 拿线上样本跑离线评测回放。④ 修复后补告警+回填回归评测集。TTL 只作一句话背景。
