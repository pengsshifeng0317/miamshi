### Q5 ｜ 题型：项目深挖 ｜ 分布式限流怎么做（本场核心，翻车）

- **我当时怎么答**：生产 2 台实例；每实例每秒只能 20 请求、两台 40 → 设 40 分布式信号量做总并发；前端分布式限流、超量排队；后面又说"两台加起来每秒 500 次请求"。
- **标准答案 / 该答成什么样**（本次已核码）：
  - **先把两个维度拆开（根本）**：**信号量管并发，QPS 管吞吐**。你说的 40 是"并发"，500 是"QPS"，不是一个东西，别搅在一起。
  - **项目现值（核码确认）**：全局分布式 semaphore = **10**（`application.yaml:111` `rag.rate-limit.global.max-concurrent`），**不是"每台 20 × 2 = 40"**，更不是每台本地并发叠加——它是**跨实例共享的全局信号量**。
  - 配套参数（核码确认）：`max-wait-seconds: 15`（:112）、`lease-seconds: 30`（:113）、`poll-interval-ms: 200`（:114）、公平 ZSET 队列 + Lua `queue_claim_atomic` 清僵尸（slack=16）、Redisson Pub/Sub `permit_changed` 唤醒（`FairDistributedRateLimiter.java:427-428`）。
  - ⚠️ **lease 是 30 秒，不是 600 秒**：`RAGRateLimitProperties.java:52` 的 Java 默认值是 600，但 yaml 覆盖为 30，以 yaml 为准——逐字稿《分布式限流怎么做.md》Q4/Q9b 写"lease 600s"已过期，背成 30s。
  - **"每台 20""500 QPS"两个数现场没出处**：跟小鹏场"每台 30×4=120"同一个病——数字现场编、没回源。背死"全局 10"，报不出就说"我记一下回你"。
- **自评**：🔴 数字矛盾（40 vs 500）+ 混淆并发/QPS + 没背死全局 10。

### Q6 ｜ 题型：项目深挖（追问） ｜ 信号量/队列机制

- **我当时怎么答**：请求进来先进消息队列排队；排队时计算总量；负载均衡均匀打两台；40 用完就排队；用户关页面/异常 → Redis 抢占判断能否入队 → 清理僵尸请求。
- **标准答案 / 该答成什么样**（本次已核码，`分布式限流怎么做.md` 有全套逐字稿，本场**一个字没抛**）：
  - 入队：ZSET + 雪花自增序号做 score（先到先服务，不用时间戳防撞）；
  - 排队：200ms 轮询 + Pub/Sub 即时唤醒双通道（`FairDistributedRateLimiter.java:339-352` 轮询、`:427-428` 广播）；
  - 抢占：Lua `queue_claim_atomic.lua` 原子「取队头窗口(slack=16)→EXISTS 判存活→清僵尸→出队」，靠 Redis 单线程保证原子；
  - 僵尸：入队前写 entry 存活标记 TTL，标记缺失 = 僵尸，Lua 里当场 ZREM；
  - 兜底：可过期信号量 lease（**30s**，yaml 覆盖），业务崩溃 permit 自动归还（`RPermitExpirableSemaphore`，`:358-361`）；
  - 拒绝体验：SSE 事件流 META→REJECT→FINISH→DONE，被拒问答写进会话记忆。
  - 这段是你**最成熟、最该主动抛**的亮点，结果只说成了"消息队列排队 + 清僵尸"的大白话。
- **自评**：🔴 白准备——整套细节没抛，只讲了骨架。
